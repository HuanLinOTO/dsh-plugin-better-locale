# @huanlin/dsh-plugin-better-locale · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 分析基线：插件 v0.3.0（`@huanlin/dsh-plugin-better-locale`）× DSH tag `dsh-v0.1.2-alpha.1`（cd5ef81481）→ `dsh-v0.1.2-alpha.2`（0a53fb55be）。
> 本指南所有 alpha.2 结论均来自对 `D:/Projects/deepseek-harness/dsh`（= `~/.dsh/source/current` 的 symlink 目标）的**只读 git 查证**（`git show` / `git diff` / `git grep`，tag `dsh-v0.1.2-alpha.2`），未对 dsh/ 做任何写操作。

## 结论

**⚠️ 需适配 —— 但仅限「翻译内容 + drift 引擎登记」层；运行时代码（apply / inject / 构建）零改动。**

一句话理由：插件是 DSH 原生语言包 API（`ctx.locale.addLanguage` + `ctx.locale.register(ns, locale, dict)`）之上的纯字典包，这套 API 在 alpha.2 **原样保留**（签名未变，见证据表 #1）；但 alpha.2 上游 i18n 内置表发生了实质漂移——**删除 1 个 `common` key、新增/改名约 99 个 key、并把 1 个旧「隐形」命名空间（`settings.agentPreset`）和 1 个全新命名空间（`schedule.catalog`）变成 typecheck 可见**，插件的编译期 drift 守卫（`upstream-coverage.ts` + `check-upstream-merges.mjs`）升级后会**双向变红**（Trespass + Drift），必须补翻译、删死键、加 2 个 merge import 才能通过 `pnpm typecheck`。不做适配的话：**运行时不会坏**（lib/ 是纯数据，type-only import 已擦除），但仓库 typecheck 红、且新 UI（Schedule 目录、连接恢复指示器、会话权限预设行、插件清单 Agent 预设分组）在这些语言下全部回退英文。
